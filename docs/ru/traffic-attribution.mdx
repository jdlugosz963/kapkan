# Атрибуция трафика и операторские представления

Эта страница описывает расширения видимости трафика в данном форке. Она дополняет исходные
[справочник конфигурации](/docs/configuration), [модель обнаружения](/docs/detection),
[панель управления](/docs/dashboard), [REST API](/docs/api) и
[уведомления](/docs/notifications), которые остаются основными для остальных функций Kapkan.

Форк добавляет четыре связанные возможности:

- настраиваемое окно обнаружения вместо жёстко заданных пяти секунд;
- разделение входящего и исходящего трафика по апстримам в **Overview**;
- отдельные списки **Top 10 hosts** для входящего и исходящего трафика в **Overview**;
- распределение по апстримам в данных атаки, REST API и callback.

## Настройка окна обнаружения

Корневой ключ `detection_window_seconds` принимает целое число от `1` до `60`. Значение по
умолчанию остаётся `5`, поэтому отсутствие ключа сохраняет прежнее поведение.

```yaml
detection_window_seconds: 15
```

Скорости являются средними за секунду на протяжении этого окна. Более длинное окно сглаживает
пакетную доставку записей NetFlow/IPFIX, но задерживает обнаружение и ослабляет короткие пики.
Изменение через reload отклоняется: требуется перезапуск Kapkan. Подробнее см.
[Обнаружение и пороги](/docs/detection).

## Имена граничных интерфейсов

Атрибуция использует адрес экспортёра и индекс интерфейса. Добавьте `interface_labels` в каждую
запись `sampling.boundary`:

```yaml
sampling:
  default_rate: 1000
  boundary:
    - exporter: "192.0.2.10"
      external_ifindexes: [13]
      interface_labels:
        13: "Транзит A"
      egress_sampling: false
    - exporter: "192.0.2.20"
      external_ifindexes: [66, 71, 72]
      interface_labels:
        66: "Транзит A"
        71: "Транзит B"
        72: "Точка обмена"
      egress_sampling: false
```

Поиск ограничен экспортёром: одинаковый ifIndex на разных маршрутизаторах может иметь разный
смысл. Одинаковые метки, напротив, намеренно объединяют несколько каналов или маршрутизаторов в
одну долю. Каждый подписанный ifIndex обязан присутствовать в `external_ifindexes`. Без метки
используется ключ `exporter:ifIndex`.

<Callout type="info" title="Направление имеет значение">
Входящий трафик атрибутируется по NetFlow/IPFIX `InIf`, исходящий — по `OutIf`. Исходящие скорости
и рейтинги заполняются только при настроенном `thresholds_outgoing`. `egress_sampling` исправляет
отдельно измеренное двойное считывание, а не выбирает направление отображения. См.
[подсчёт на граничных интерфейсах](/docs/configuration).
</Callout>

Если ifIndex неизвестны, временно включите `sampling.boundary_debug`, сравните
`kapkan_engine_boundary_debug_bytes_total` со счётчиками маршрутизатора и затем отключите метрику.

## Что показывает Overview

**Aggregate traffic** суммирует текущие скорости хостов с поправкой на сэмплирование. Отдельные
полосы для входящего и исходящего трафика показывают метку, Мбит/с и процент видимого итога.
Выводится до 16 апстримов, отсортированных по Мбит/с.

Две карточки **Top 10 hosts** независимо сортируют направления по Мбит/с, затем PPS и IP-адресу.
Это снимки из памяти, ClickHouse не требуется. Исходящий список пуст без `thresholds_outgoing`.
См. [Панель управления](/docs/dashboard).

## REST API

`GET /api/v1/hosts` добавляет к каждому хосту два необязательных массива:

| Поле | Направление | Элемент |
| --- | --- | --- |
| `upstreams` | входящее | `{ "key": string, "mbps": number, "pps": number }` |
| `upstreams_out` | исходящее | `{ "key": string, "mbps": number, "pps": number }` |

Это скорости с поправкой на сэмплирование, усреднённые за `detection_window_seconds` и
отсортированные по Мбит/с. Панель суммирует их по хостам, видимым текущему токену. См.
[GET `/api/v1/hosts`](/docs/api).

## Отчёты об атаках и callback

При включённом сэмплировании атак `GET /api/v1/attacks`, карточка атаки, webhook и exec-hook в
формате `kapkan` содержат `sample.top_upstreams`:

```json
{
  "sample": {
    "top_upstreams": [
      { "key": "Транзит B", "packets": 1263000, "bytes": 1542000000 },
      { "key": "Транзит A", "packets": 421000, "bytes": 489000000 }
    ],
    "total_packets": 1684000
  }
}
```

Это скорректированные счётчики, а не текущие скорости. Доля пакетов равна
`item.packets / sample.total_packets`; знаменатель не обрезается. Направление выбирает `InIf` или
`OutIf`. Версионированный контракт:
[Схема callback](/docs/notifications); эталонный файл —
`docs/callback-schema.json` в этом репозитории.

## Проверка внедрения

1. Настройте граничные интерфейсы и метки; одинаковая метка объединяет каналы.
2. Для исходящей видимости включите `thresholds_outgoing`.
3. Проверьте `kapkan -check-config /etc/kapkan/config.yaml`.
4. После изменения окна перезапустите сервис; только метки можно применить через
   `systemctl reload kapkan`.
5. Проверьте `upstreams`, `upstreams_out` и оба направления в Overview.
6. При тестовой атаке проверьте `sample.top_upstreams` в API и приёмнике callback.
